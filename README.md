# NOOK (Mobile App)

> **My minimal reading nook**  
> _"읽는 순간부터 간직하는 순간까지 — 나만의 미니멀 독서 아카이브, nook"_

## 프로젝트 소개

- [오늘 읽은 기록 & 한 줄 감상평 작성] ➔ [나만의 서재 완성]

  위와 같이 기록이 서재 형성으로 자연스럽게 이어지는 경험을 통해 직관적이고 즐거운 독서 습관을 만들어줍니다.
  단순하고 차분한 기존의 감성 스타일을 깨고 네오 브루탈리즘 디자인 요소를 더해 트렌디하고 개성 있는 독서 아카이빙 환경을 제공합니다.

## 타겟 유저

- 자신의 독서 기록을 한눈에 보고 감상평과 함께 책을 아카이빙하고 싶은 유저
- 단발성 기록에 그치지 않고 지속 가능하고 즐거운 독서 습관을 들이고 싶은 유저

## 주요 기능

### 1.독서 아카이빙 & 서재 관리

- 3가지 상태 분류: `읽는 중`, `다 읽은 책`, `읽고 싶은 책`으로 내 서재를 직관적으로 구조화<br/>

  <img width="390" height="810" alt="완독" src="https://github.com/user-attachments/assets/39c015ae-e812-491b-833d-c5cccca0838a" />

- 자동 상태 전환:
  - 시작일만 입력하면 자동으로 `읽는 중` 탭에 등록된다.
  - `읽는 중` 서재에서 책을 클릭해 기록 페이지로 이동한 뒤, `완독` 버튼을 누르면 오늘 날짜로 자동 완독 처리되어 `완독` 탭으로 이동한다.
  - 책을 추가할 때 시작일과 완독일을 처음부터 함께 입력하면 바로 `완독` 탭으로 등록되도록 유연하게 구현했다.
- 페이지 두께 반영: 완독한 책 목록에서는 도서 페이지 데이터에 따라 실제 책 두께가 반영되어 읽은 책이 차곡차곡 쌓이는 시각적 재미를 제공한다.
- 타임라인 독서 메모: 한 번 작성하고 끝나는 메모가 아니라 책을 읽는 동안 매일매일 오늘의 감상평을 계속 추가하며 독서 흐름을 누적 아카이빙할 수 있다.

## 서비스 구조

```text
[Home]
 ├── 읽는 중
 │    ├── 책 리스트 ──> 기록 내용 ──> [기록 추가] / [완독] / [삭제]
 │    └── [추가 버튼] ──> 책 검색 ──> [기록 추가]
 │
 ├── 다 읽은 책
 │    ├── 책 리스트 ──> 기록 내용 ──> [삭제]
 │    └── [추가 버튼] ──> [기록 추가]
 │
 └──  읽고 싶은 책
      └── 책 리스트 ──> 책 상세 정보

[Search]
 ├── 검색 바
    └── 책 리스트 ──> 책 상세 정보
 ├── 장르별 탭
 └── 베스트셀러
```

## 프로젝트 회고 및 발전 방향

이번 프로젝트를 진행하며 단순히 기능을 구현하는 데 그치지 않고 사용자 경험최적화, 외부 API 연동, 데이터 구조화 등 다양한 측면에서 고민하며 성장할 수 있었다. 프로젝트를 거치며 느낀 아쉬운 점과 배운 점을 다음과 같이 정리했다.

- 사용자 데이터 관리 및 확장성 한계

  현재는 LocalStorage 기반으로 데이터를 저장하여 단일 기기에서만 기록이 유지되는 한계가 존재한다.
  향후 로그인/회원가입 시스템을 구축하여, 유저별 독립된 서재를 제공 가능하도록 확장할 예정이다.

- 미션 시스템(동기부여 기능) 미구현

  초기 기획 단계에서 구상했던 동기부여 랜덤 미션 및 책갈피 뱃지 수집 시스템을 기한 내에 완성하지 못해 아쉬움이 남았다.
  미션 동작 기능(주간 기록, 새로운 장르 탐험 등)을 구체화하고 랜덤 부여가 가능하게 완성하여 유저가 지속적으로 독서에 흥미를 느낄 수 있는 환경을 만들고자 한다.

- 다량의 데이터에 대응하는 UI/UX 레이아웃 보완

  서재에 수십 권 이상의 도서 데이터가 쌓였을 때를 고려한 '읽는 중' 및 '완독' 탭의 UI/UX 처리가 미흡했다.
  많은 양의 데이터를 효율적으로 보여주기 위해 무한 스크롤, 리스트 뷰 전환 기능, 정렬 및 필터링 옵션을 보완하고자 한다.

- 유저 친화적인 Form 입력의 중요성

  책 추가 페이지를 지속적으로 리팩토링하는 과정에서 단순히 기능이 동작하는 것을 넘어 사용자가 한눈에 알아보기 쉬운 인터페이스를 구성하는 것이 얼마나 중요한지 깨달았다. placeholder 텍스트 직관화, 유효성 검사 메시지 등 세심한 요소까지 깊이 고민하여 유저 접근성을 높여야한다는 것을 깨달았다.

- 실시간 검색 vs 버튼 검색

  고민한 지점
  - 실시간 검색: 입력과 동시에 결과를 보여주어 편의성은 높았으나, 로딩 처리와 잦은 화면 전환 때문에 UI가 다소 산만해 보이는 현상이 있었다.
  - 버튼 클릭 검색: 화면 전환은 안정적이었으나 클릭 단계가 늘어나 사용자 경험의 흐름이 단절되는 아쉬움이 있었다.

  개선 방향
  - 스켈레톤 UI를 적용하고 타이핑에 대하 반응 속도를 자연스럽게 조절하여 통해 실시간 검색의 시각적 피로도를 낮추고 검색 범위를 제목 + 작가 통합 검색으로 확장하여 정확도를 높일 생각이다.

- 외부 Open API 제약사항 사전 고려의 필요성

  무료 API를 활용하면서 응답 속도 지연, 이미지 퀄리티 제한 등 예기치 못한 한계를 경험했다.
  개발 초기 단계에서 외부 API의 제약 요소를 미리 생각하여 이를 고려한 시스템 설계 및 UI 기획이 필요하다는 것을 깨달았다.
